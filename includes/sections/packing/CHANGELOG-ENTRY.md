Added Packing section — which bag every fish goes in and which box an order fits in, so that packing no longer lives in one head. **Bags**: a list of the standard bags under FisHotel Tools → Packing (a name, an optional width and length in inches, a sort number; nothing is seeded; a bag keeps its id for good, so a rename changes nothing on the products that use it, a removed bag's id is never reused, and an out-of-date page cannot bring a removed bag back under a new id). **Bag size per fish**: an admin-only *Bag size* dropdown on every product variation and on simple products (Shipping tab) in the classic product editor, stored as the hidden meta `_fh_bag_size` (a bag id) through the product object behind `manage_woocommerce` and the section's own nonce — a record only: not an attribute, no variation, no term, never written to an order line, and the section registers no hook at all outside wp-admin, so it never appears on the storefront, in the cart, at checkout, in e-mails, on invoices, in My Account or in the customer-facing REST / Store API (a front-end request loads nothing but the section's own file, hooks nothing and reads no option). **Size → bag**: a table mapping each fish size to a bag — the sizes are the Clean Room's list when that section is switched on (`Sizes::standard()`, reached through `class_exists` / `method_exists`), else the terms of the product attribute whose name contains "size", found by this section; a variation's own value overrides the map, and the same map answers for fish that are not shop products (an invoice line, an unlisted fish) from the size on the line. *Fill empty ones from the map* previews how many variations it would set (and how many carry a size with no bag, no size, or belong to a product that is not packed in a bag) and then sets, a batch at a time, only fish variations that have no value — each checked once more just before it is written; products that are not packed in a bag are left alone (the checkbox below; with no choice stored, the fish categories). **Boxes**: the standard boxes come from ShipTracker when the active build provides them (`FST_Settings::get_standard_boxes()`, guarded with `method_exists`) and otherwise from this section's own list (name, length, width, height in inches); the Boxes tab says which. For each box and each bag the owner types how many fit (blank = that bag does not go in that box); the numbers follow a box by its name, through a rename in the own list (each row says which box it was — never its position, so a form posted twice or from an out-of-date page moves nothing), or by its size when it moved to ShipTracker's list. A save that redraws the page keeps its button disabled until the page is back, and *Save boxes* refuses to run while *how many fit* holds unsaved numbers. **The suggestion** (a pure class): bags needed = each fish line's quantity in its bag size, one bag per fish (the filter `fishotel_packing_fish_per_bag` is the seam for more); the fill of a box = the sum over the bag sizes of bags needed ÷ how many fit; the smallest box by volume whose fill is at most 100 % is suggested; when none holds it all the order is split — the largest box filled first, bulkiest bags first, then the smallest box that holds the rest — and says so; a box at or over the threshold (a setting, 90 % by default) is flagged *on the line* for the owner to confirm; lines with no bag size are listed by name and the suggestion is marked incomplete; items that are not fish (the Ship Day pick list's rules and the product's *Livestock — packed in a bag* checkbox, below) are ignored and named; a bag no box takes is set aside and named. **On the order**: a *Packing* box on the order screen, legacy and HPOS alike — each fish line with its bag and where it came from, the bags by size, the suggested box with its fill, the on-the-line flag, and a Confirm / change / clear control that stores the chosen box as order meta (`_fh_packing_box`, `_fh_packing_box_name`) through the order object, with `manage_woocommerce` and a nonce; no note, no e-mail, no status or stock change. *Confirm* stores only the suggestion that was on the screen: when the order or the numbers changed since the box was drawn it stores nothing and redraws the box with the suggestion as it stands. A combined box is read through its live source orders, and an order that went into one points to it. **Contracts**: `fishotel_packing_suggest( $order_id )`, `fishotel_packing_bag_for_item( $order_item )` (for the pick list), `fishotel_packing_confirmed_box( $order_id )`, plus `fishotel_packing_bag_for_product()` and `fishotel_packing_bag_for_size()` — each with a filter of the same name, answering "nothing" while the section is off — and the actions `fishotel_packing_box_confirmed` / `fishotel_packing_box_cleared`. Storage is one option that is not autoloaded (`fishotel_packing_settings`): no table, no cron, no REST route. **Bags are for livestock only**: a product-level checkbox *Livestock — packed in a bag* in the product editor's Shipping tab (simple and variable products), stored on the parent product as the hidden meta `_fh_packs_in_bag` (`yes` / `no`) through the product object, behind `manage_woocommerce` and the section's nonce like the Bag size — and as silent: admin-only, never on the storefront, in the cart, at checkout, in e-mails, in My Account or in the customer-facing REST / Store API. With nothing stored the box is ticked for a product in a fish category and unticked otherwise, so existing fish need no click and medication, food and dry goods show no bag fields; a save stores a choice only when the owner clicked the box, and a save that does not carry it (quick edit) changes nothing. The Bag size dropdowns — the simple product's and every variation's — show only while the box is ticked, and follow it at once without a reload, the variation panels that load later included (one class on the product-data box, one stylesheet rule); a new product ticks itself when it is put in a fish category. Unticking deletes nothing: a Bag size stored earlier is kept and stops counting. **One rule** now says what is packed in a bag, everywhere — the order's Packing box, `fishotel_packing_suggest()`, `fishotel_packing_bag_for_item()` / `fishotel_packing_bag_for_product()`, the fill tool and the product editor: ticked = yes whatever the category; unticked = no, even in a fish category and even with a Bag size stored; no stored choice = the fish categories, as before. This replaces "a product with a Bag size of its own counts as a fish whatever its category" — which still holds for a product whose box was never touched, so nothing already set changes by itself. A variation is read from its parent product; a line whose product is unticked is ignored by the suggestion and named as that, apart from what is not a fish; *Fill empty ones from the map* fills a ticked product whatever its category and leaves an unticked fish alone, counting it.
