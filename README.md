# FisHotel Misc Plugin

A modular container plugin for WordPress with a dark theme admin interface.

## Overview

FisHotel Misc Plugin provides a framework for managing independent feature "sections" through a unified dark-themed dashboard. Each section is a self-contained module that can be enabled or disabled independently.

## Where things are

**FisHotel Tools** in wp-admin lists the sections that are switched on,
related screens together: **Dashboard**, **Today** (the one to-do page),
then **Fish room** — Clean Room; **Customers** — Invoices, Requests,
Lost Fish; **Shipping** — Packing, Foam Cuts, Weather; **Site** — Health,
Snippets, Shop App and every other section. The Dashboard shows the
section cards under the same headings, each saying in one sentence what
the section is for and what switching it on starts by itself. Every
section arrives switched off. The order and the sentences live in
`includes/class-layout.php`; no page address changed.

At the top of the Dashboard (and on the Health screen) the **FisHotel
versions** card lists every FisHotel build on the site — FH Boards,
FisHotel SMTP, ShipTracker, Batch Manager, Misc, the theme, and WPIT
Updater when it is there — with its version, its folder and whether it is
on, and warns when one plugin sits in two folders (a zip that unpacked
under another name) or a FisHotel plugin is switched off. It only reads
what the Plugins page reads (`includes/class-versions.php`).

One home per list:

| List | Its home | Elsewhere it is only read, with a link there |
|---|---|---|
| Boxes | ShipTracker → Settings → Boxes & label costs | Packing → Boxes, Foam Cuts → Boxes & cut lists (their own lists are hidden while ShipTracker's is in use, and come back if it has none) |
| Sizes | Clean Room → Settings → Sizes | Packing → Sizes (which bag each size goes in) |
| Medications | Clean Room → Settings → Medications | — |
| Supplies (foam, bags, paper): counts and cost per box | ShipTracker → Settings → Boxes & label costs → Supplies | Foam Cuts → Stock keeps only its sheet ledger and leftovers |

## Words used on the screens

One word for one thing, on every screen of these sections:

| Word | Means | Not |
|---|---|---|
| **tank** | one tank, numbered by the rule *hundreds = building, tens = level, ones = position* (tank 521 is in building 500). A temporary tank is a numbered **slot** in building 900. | aquarium |
| **building** | a numbered group of tanks that share one water — 100, 200, … (Clean Room README, *The numbering rule*) | rack, room |
| **system** | the water a building's tanks share (sump included): "whole system" doses and readings, "system gallons" | building (the place), tank |
| **tank group** | the fish of one species that arrived and live together — a *stay* on the Clean Room's Stays tab | batch (a supplier order) |
| **bag** | the bag one fish is packed in; its standard sizes are Packing → Bags | pouch |
| **box** | the shipping box an order goes out in (its list is ShipTracker's); a supplier's box only in the Clean Room's *Box rates* | carton, shipper |
| **case** | Lost Fish: one paid-for fish (or several) that was lost, and what the customer is offered | claim, ticket |
| **request** | Requests: a fish somebody asked for; its fee is sent as a **bill** with a pay link | wish, order |
| **invoice** | Invoices: the hidden product a customer adds to the cart to pay for the fish picked for them | bill (that is a request's fee) |
| **e-mail** | written with a hyphen everywhere | email |
| **fish room** | the room the tanks are in, and the screens the Shop App opens there | wet room, shop floor |

## Requirements

- WordPress 5.8+
- PHP 7.4+

## Installation

1. Upload the `fishotel-misc-plugin` folder to `/wp-content/plugins/`.
2. Activate the plugin through the **Plugins** menu in WordPress.
3. Navigate to **FisHotel Tools → Dashboard** to manage sections.

## Architecture

```

├── fishotel-misc-plugin.php        # Bootstrap & autoloader
├── includes/
│   ├── class-plugin.php            # Main plugin orchestrator
│   ├── class-section-manager.php   # Section discovery & toggling
│   ├── class-layout.php            # Menu order, Dashboard headings, one sentence per card
│   ├── class-versions.php          # The "FisHotel versions" card: every FisHotel build, its version, folder, on/off
│   │                               # (the main file also includes sections/site-snippets/early-loader.php at load time)
│   └── sections/
│       ├── announcer/              # Announcement bars
│       ├── sticker-giveaway/       # Free sticker picker at checkout (+ $1 add-ons)
│       ├── lottery-draw/           # Verifiable lottery for group orders
│       ├── weather/                # Nightly delivery-day weather notes + packing actions
│       ├── health/                 # Shared error log, failure capture, FisHotel Health widget + page
│       ├── today/                  # Today at FisHotel: next delivery days, holds / UPS Store, missing weather / invoice / tracking; one line for the tanks' to-do list when the Clean Room is on
│       ├── clean-room/             # Where every fish is: Spa / Clean Room tanks, stays with replayed events, QR + voice Front Desk, protocol to-do, room board, supplier orders, chosen sale dates, standard sizes, percent-of-a-box costing with remembered shares, unknown / mislabeled fish with one correction, a dose calculator over an editable medication list, temporary (hospital) tanks with their own schedules, one To do list by water system, Stats views (compare years, species, prices to raise, real sales)
│       ├── requests/               # Requests: a request sheet for the fish people ask for — private links, added by hand or by another section, an optional fee, a state that follows the fish from the supplier order to "ready"
│       ├── lost-fish/              # Lost Fish: a paid-for fish that is lost — the tanks checked for a spare, else a case with the numbers for every choice, the e-mail behind one click, the customer's private page
│       ├── invoices/               # Invoices: a customer's invoice built from a pick list (tank groups, shop products, the species list, typed), pre-checked against what the customer already has, published as the hidden product
│       ├── packing/                # Packing: the standard bags, a bag size per fish, how many bags fit each box, the box suggested for an order and the one confirmed
│       ├── foam-cuts/              # Foam Cuts: a cut sheet for the foam that lines a box — sheets and labelled leftovers in stock, a plan for the boxes of the day, straight edge-to-edge cuts
│       ├── shop-app/               # Shop App: "FisHotel Shop", an installable web app for the fish room — enrolled devices, a PIN per person, the Front Desk's tank screens without a WordPress login
│       └── site-snippets/          # Snippets: the site's own code as files in GitHub (was Code Snippets), switched on/off, run at plugins_loaded:1; plus an editor for snippets written in wp-admin (named editors only, history, audit log, export to GitHub)
├── admin/
│   ├── css/admin-style.css         # Dark theme styles
│   ├── js/admin-script.js          # Toggle & AJAX handling
│   └── views/dashboard.php         # Dashboard template
├── tests/layout-test.php           # The menu order and the Dashboard's headings
├── tests/hook-callbacks-test.php   # Every hook / menu / REST callback names a method that exists
├── tests/versions-test.php         # The FisHotel versions card and its warnings
└── README.md
```

Each section is switched on and off in **FisHotel Tools → Dashboard** and is described in its own folder: `README.md` (what it does, its screens, its tables and options, its hooks and functions for other code) and, where it has headless tests, `tests/README.md` (how to run them and what each covers, plus what to check by hand on a real site). The sections added in 0.46 — `requests/`, `lost-fish/`, `invoices/`, `packing/`, `foam-cuts/`, `shop-app/` — each have one; so do `clean-room/` (the dose calculator, the temporary tanks, the To do list and the Stats views are chapters of its README), `today/`, `health/`, `weather/`, `lottery-draw/`, `site-snippets/`, `sticker-giveaway/` and `announcer/`.

What the sections offer each other — each function exists while the plugin is active and answers "nothing" while its section is off (null, an empty list, `available: false`; a `WP_Error` from the one that creates), so guard with `function_exists()` and read the answer: `fishotel_cleanroom_product_facts()` and `fishotel_cleanroom_todo()` (Clean Room; actions `fishotel_cleanroom_order_line` and `fishotel_cleanroom_event_recorded`), `fishotel_requests_create()` and `fishotel_requests_get()` (Requests), `fishotel_invoices_lines_for_product()` and `fishotel_invoices_for_order()` (Invoices; action `fishotel_invoice_paid`), `fishotel_lostfish_cases_for_order()` (Lost Fish), `fishotel_packing_suggest()`, `fishotel_packing_bag_for_item()` / `_for_product()` / `_for_size()` and `fishotel_packing_confirmed_box()` (Packing), `fishotel_foam_cuts_plan()` (Foam Cuts). Each section's README has the shapes.

## Creating a Section

1. Create a directory under `includes/sections/` (e.g. `my-feature/`).
2. Add a class file named `class-my-feature.php`.
3. Implement the required static methods:

```php
namespace FisHotel\Misc\Sections\My_feature;

class My_feature {

    public static function get_section_info() {
        return [
            'name'        => 'My Feature',
            'description' => 'A brief description.',
            'icon'        => 'dashicons-star-filled',
        ];
    }

    public static function boot() {
        // Initialise your feature hooks here.
    }

    public static function register_menu() {
        // Optional: add a submenu page.
    }
}
```

The Section Manager will automatically discover and register the section.

0.46.10 — Sticker Giveaway: **designs from variations, and a stock table with "Reorder at".** The shop keeps its stickers as one product with a variation per design, so the pool no longer has to be simple products: the product search on FisHotel Tools → Sticker Giveaway also finds a product with variations, and picking it lists its variations underneath, each with a tick — one ticked variation is one design. All are ticked when the product is first picked; a variation added to the product later is listed unticked and marked *New — not offered yet*, never offered by itself; a variation that leaves an attribute on "Any" cannot be a design, and the page says so on its row. On the checkout picker a design is shown under its own attribute value as typed ("Night Glow", not "Reef Stickers - Night Glow") and with its own picture, else the product's; in the cart it is a normal variation line, so the order screen, the emails and the invoice name the design. An attribute typed on the product and a global one both work. **One count, and it is WooCommerce's**: a design's count is the stock number on the product's own page — the variation's, or the product's when it keeps the stock for its variations, or the simple product's. A free sticker, an add-on and a normal shop purchase all come out of that one number through WooCommerce's own stock handling, exactly as for any product; the section keeps no count of its own. A design is offered while at least 1 is in stock (also when the product allows backorders: never a sticker that is not there). **Stickers in stock**: a new table on the page, one card per design — picture, name, *In stock*, a status (*OK* / *Reorder* / *Out*) and two acts, each with its own number box and done at once: **Add stickers** (a new box arrived: adds the number) and **Recount** (what you counted by hand: sets the number). Both change the product's stock in WooCommerce itself, so the product page shows the same number. A product that does not manage stock reads *not tracked* and has no reminder until "Manage stock" is ticked. **Reorder at**: a number per design (blank = no reminder) — your signal to count the stickers by hand and reorder. At or below it the design reads *Reorder* in the table and on the Today page and its widget ("Stickers to reorder: Night Glow (40 left)", through Today's own seam for other sections' lines), and **one email** goes to WooCommerce's stock notification address (else the site admin) when the stock first drops to the number — "Night Glow is down to 40 (reorder at 40). Time to count the stickers by hand and reorder." — with no second one until the stock is back above it; *Email me when a design needs reordering* switches the emails off. The check runs whenever WooCommerce changes that product's stock (an order, the product page, Add stickers, Recount) and when the settings are saved; WooCommerce's own low-stock emails still exist, are separate and are not changed. **A sticker never blocks an order and never costs a sale**: when the stock no longer covers a sticker line — it ran out between the picker and Place Order, or the customer bought the last ones of that design the normal way — the sticker line is cut down or dropped quietly before WooCommerce's own "not enough stock" check, and the normal purchase keeps whatever the stock allows. A simple-product design gains *Reorder at* and is otherwise as before. Also: a sticker line of a variation shows the variation's own picture in the cart and the checkout statement; and the page no longer sends you off to re-categorise a sticker product that sits in *Merchandise* — the current theme leaves sticker lines out when it picks the cart wording, so the warning (and the one about a short description) is only shown for a theme that does not yet, and the note about the shipping class says what is true today. The page stays one page and needs no sideways scrolling on a phone. No table and nothing saved on a product; the "Reorder at" numbers are in the section's settings, and which emails have gone is one small option. No pace ("about N a week") is shown — WooCommerce has no cheap, truthful figure for it. See `sticker-giveaway/README.md`, *Stock*.

0.46.9 — Clean Room: **Import lines** on a supplier order. An order is 150 fish, and typing them line by line is over: under the lines of an order — a new one or a saved one — **Import lines…** takes pasted rows (copied out of a spreadsheet, or comma-separated, with or without a header row) or a file (CSV, TSV, XLSX, XLSM), and *New order from pasted lines / a file* on the Arrivals list opens a new order with it. Two moments, two big buttons. **This is what I ORDERED** — the order sheet, which is usually the supplier's whole price list with an ORDER column filled in: the header row is found under the title rows (the row with the most headings, so a letterhead line above it is never taken for it), "order" is the quantity and "stock" never is, and only the rows with an order quantity become lines ("61 of 1,188 rows have an order quantity"), each with its ordered count, received left empty, its per-box count, its price and the supplier's code; the order becomes *ordered*. **This is what ARRIVED** — the supplier's invoice when the boxes land: every row is paired with a line on the order (by the supplier's code first, then by fish and size; a pairing made by hand wins; a row that is plainly another line's fish goes to that line whatever its code says, a row without a size against a Small and a Large line waits for you to say which, and a row that fits two lines of the same fish and size — ordered twice, or two sizes that *Tidy up the sizes* made one — goes to the line with its price, or waits for you when nothing tells the lines apart) and shown in four groups — *Came as ordered*, *Came short / over*, *Did not come* (received becomes 0 and the line stays, so the fill rate is true) and *Extra / substituted* (a new line with ordered 0, or "this came instead of …") — with the foot "Ordered 150 · arrived 104 · 69% filled · 11 kinds did not come". Confirm writes received, and the price, DOA, box and percent of a box only where the line's own field is still empty (a typed price is kept unless *use the file's price* is ticked). A saved order that is *ordered* opens the importer on **This is what ARRIVED**, and a sheet of received counts read as an order sheet offers the switch. Columns are found by the text of their headings, never by position; without a recognisable header there is a dropdown above each column and nothing can be imported until a fish and a quantity column are chosen. Every row shows the fish as typed and its match — the same matching the phone uses — with the best candidates, *use as typed* and *Unknown fish (??)*; a weak or ambiguous match is flagged and never chosen for you; a size inside a name ("(L)", "- S") moves to the Size only when it is one of the standard sizes (`3-5"` and `3.5"+` are each read as themselves; a bare "5" is never a size), and a size from a column of its own that is not one of them is kept in the line's notes; numbers that cannot be read are flagged on their cell (a decimal comma is not assumed, a formula-looking cell is text); totals, headings, repeated headers and fee lines — under whichever heading a fee's words stand — are left out and counted, while a row with a supplier's code or a scientific name is never taken for a fee; a packing list that names its fish by scientific name alone is read too. **Saved layouts**: once the columns were set by hand, *Remember this layout for <supplier>* keeps them — one for the order sheet and one for the invoice — and the next file from that supplier is read the same way by itself; another supplier's layout that fits is only offered ("This looks like …'s sheet. Use that layout?"), and Settings → *Saved import layouts* lists them with Forget. **An invoice is a PDF, often a scan**: *Copy the instructions* beside the box gives a short text to paste into a chat assistant together with the invoice; the block it gives back (asked for inside a code block; an answer drawn as a table is read too, and a block whose tabs were lost says so instead of guessing) is pasted into the same box, carries the box and the origin of every row (an invoice with boxes from two origins asks which sections belong to this order) and, in a second small part, the fee lines — "Fees on this invoice: tariffs … · everything else …" fills the order's empty Tariffs and Import & re-ox fees fields with one tick — and the invoice's subtotal, which is checked against the rows. For the day there is no file: **Received: all as ordered** fills the empty received fields, and Enter or Tab moves down the received column. An import never removes a line, never changes a line that is already checked in, and never checks anything in; a confirm is the page's own Save with the rows added, so an imported line is costed and remembered exactly as a typed one. Under the hood: an order's lines now travel to the server as one field, so an order of 150 lines is no longer at the mercy of the server's limit on form fields — and a field that does not arrive in one piece refuses the save instead of emptying the order. An uploaded file needs an administrator and is deleted as soon as it was read; pasting works for everyone who can edit orders. No table changes: the layouts are one option. **Entry and Numbers** — the same order page, no longer one table that scrolls to the right for ever: the lines have **two views**, switched by two big tabs and remembered per person. **Entry** (where an order opens while it is being worked on — and always while it has no line yet) shows only what is typed — # · Fish · Sci name · Size · Ordered · Received · Cost · DOA · Box # · % of box · Tank (Bags in bag mode) — with number boxes as narrow as their numbers, so a whole row fits a 1280-px window; fish per box, the typed survivors and the supplier's code sit behind *More columns* (a row still fits 1280 px with them on; on a 1024-px window the scientific name reads under the fish); **Received: all as ordered** is in its head; Enter goes down a column, Tab goes down Received, then DOA, Box # and % of box, and neither ever saves by accident. **Numbers** shows the fish and what the site works out, nothing to type — shop price · landed per fish · the target price headed "400%" · profit · margin · Worth it? · revenue · survived · live · sold — under a panel of the order's grand total, up or down, revenue, fill rate, survival, DOA and its cost, and credit. Nothing is lost by hiding: both views are the same form, and a Save from either posts every field. **"Worth $" is no longer typed**: what a fish sells for is read from its product in the shop — its regular price, so a sale never turns "Worth it?" over (the variation of the line's size, else the lowest price) —, else from the species list, every time the order is opened; a pencil in Numbers types a price of your own when you plan one. **A closed order is frozen**: closing it writes that day's prices on its lines, and its numbers — and the past years of the Stats — no longer move with the shop. A fish with no shop price says "no shop price yet" — never "No", never −100% — and is left out of the revenue and of "up or down"; the panel says how many lines that is, and the Stats count the same way. The worth-it rule and its 2.75 are exactly the sheet's, now in plain words: "Worth it when the shop price is more than 3.75× what the fish cost landed"; an order whose lines all carry a typed price is costed to the cent as before. **Split**: a small button in the Tank cell opens rows of "how many → which tank" under the line (Spa tanks and quarantine temporary tanks, the empty ones first, no tank twice), with **1 per tank** over the next empty Spa tanks of the order's building and a running "6 of 6 placed". *Check in received fish* then checks the line in exactly as you would by hand — the arrival into the first tank, the DOA loss, one move of a smaller count per further tank — so Undo, the Board and the Stats need nothing new, and a second click still creates nothing; the tanks a split was planned into are kept free for it, so a line left on auto never lands in one of them. A line that was split still counts as one line: a fish lost or sold in any of its tanks is lost or sold on the order (a group split by hand on the phone used to stop counting the half that moved). The site remembers which fish were split last time and opens the split on their next line as a **proposal** — dashed rows, nothing planned until you press *Use this split* or change a row, and "1 per tank" laid out only for as many fish as went one per tank last time — which *Keep together* takes away: never something done behind your back. No table changes: the planned splits and that memory are one option, the view you left the page in is kept with your user.

0.46.7 — Clean Room: **Tidy up the sizes**, a tool on Settings → Sizes that brings the shop's long list of fish sizes down to a short one. Nothing runs by itself — no cron, nothing on activation or on this update: only its buttons do anything, and it is the owner's (`manage_options`, its own nonce). It starts from a short list of ten (`1-2"`, `2-3"`, `3-4"`, `4-5"`, `5"+`, `Small`, `Medium`, `Large`, `Pair`, `All`), which can be edited, and a map with one row per size in use, filled in by a rule and open to change row by row: an inch range goes to the inch size that holds its midpoint, an "and up" size to the inch size that starts at it, a word is never guessed into inches, and the in-between words (`Small-Medium`, `Medium-Large`, `Large-XL`) are taken off the products. **Show what would change** is a dry run that writes nothing and names every fish it would touch. **Apply** asks for a backup tick and the word TIDY, works in small steps that can stop and carry on, and never deletes a variation: a renamed one keeps its number, price, stock and SKU; one taken off is switched off (WooCommerce's own "Enabled" box) and kept. A fish that is for sale today in a size being taken off is left until it sells out unless the owner picks otherwise (the size reads *retiring*); a fish whose two sizes would become one is left untouched and listed until the one to keep is picked. Afterwards a **Sizes to fill in** list names the fish left without a size, and **Undo** puts back the last run (three are kept), skipping and naming anything changed by hand since. Stays, order lines, box shares, requests, lost-fish cases, invoice lines and the Packing size map follow the new sizes; a Clean Room stay keeps a retired size, and a past order still shows the size it was bought in. Two tables, `fh_sizes_tidy_runs` and `fh_sizes_tidy_items`, are created on the first Apply only. To know before running it: run it at a quiet hour, since a renamed fish drops out of open baskets; a fish left with no size reads "Currently unavailable" with no price until a size is added; and the fish page still lists word sizes A–Z (the theme's own order). Also: the size pickers follow the order set on the attribute (WooCommerce's term order, which the section read from the wrong place). See `clean-room/README.md`, *Tidy up the sizes*.

0.46.6 — Clean Room: **Add fish already here**. Fish that were in the room before it was on the site — some of them for months — can now be put straight into the tank they stand in, any tank, with no Spa step: on the phone every tank screen has **+ Add fish already here** under its six buttons (Arrival keeps its rules for new fish), and the Stays tab has the same as a small form. It asks for the fish (the Arrival search, *Unknown fish (??)* and an unlisted name included), how many and the size, then three questions that start on **Unknown**: *Arrived on*, *Cleared on* (in a clean tank a fish counts as cleared, its date Unknown unless given; in the Spa "Not cleared yet" is the default) and *Where it came from* (the supplier and the origin). Unknown is a state, never a guessed date: the stay's dates stay empty, the screens say "arrived: unknown", "cleared: unknown" and "day ?", a Spa group without an arrival date says "treatment day unknown — set the arrival date", and a date filled in later (Dates on the phone, Edit or Cleared… on the Stays tab) makes it behave like any other group. Moves, splits, losses, shipped, recounts, sale dates, the To do list and Undo all work with empty dates. The stay's source is the new `existing`, so the Stats tell these fish apart: a card *Fish already here (added by hand)* counts what is alive, shipped and lost and says how many were left out of the batch figures (they belong to no supplier order). The product facts give null for a date nobody knows; nothing for customers changes (the theme does not read them yet). Schema 1.7: the stays' check-in may be empty and the stays and their events take the source `existing` — an upgrade that keeps every row (an explicit `ALTER … MODIFY checkin_date DATE NULL`; the gate waits for it). The new act works under a Shop App PIN like every other Front Desk write; the Board's form is wp-admin only. Undo of "Not cleared" now gives back what the group held — its cleared date, or "cleared: unknown" — instead of "That can no longer be undone", and on the phone an empty cleared box on a group cleared on an unknown date asks for a date rather than unsetting it. On the Events tab a split half of such a group reads "1 arrived in Tank …" like any split half, not "added as already here"; and the Stays tab's form shows only the cleared hint of the kind of tank picked. The green message with **Undo** on the phone no longer comes up over the page, where it lay on whatever was there (with the new third row of buttons, on the Lost / Shipped / Move row itself): it has a place of its own that is always there — a **status line**, the first row of the button bar on every Front Desk screen (alone at the foot of the picker and the day's list), one line at one height. A message changes no size and no place of anything, so it covers no button and a second tap lands where the first did. In the line: **↶ Undo** at the left, only while there is something to undo (on a sheet, where it sits just above Cancel / Save, a tap on it opens the message first, so one stray tap takes back nothing and drops nothing that was typed); the words, cut with "…" when long — a tap on them opens the whole message, with the Undo; and a thin bar that runs out with the 10 seconds. Then nothing moves: the Undo turns quiet (outlined) and the words read "Last: … · 2 min ago". The Undo stays, on sheets too, until the next write, and leaves before the 15 minutes the undo is good for are over; a phone that slept is not left offering an undo that is over. An error is said in the same line and never throws away an Undo that is still good — its place is kept, empty, until it is back. A request that got no answer (no signal) is said in plain words — "No connection — not saved. Try again." — not in the browser's ("Failed to fetch"). A screen reader is told each message's words once.
